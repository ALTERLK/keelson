## 先弄明白它是什么

**大模型本身只会输出文字。** 你问它“帮我修一下这个 bug”，它能写出一段修复方案，但它碰不到你的文件，也跑不了测试。

要让它真的动手，得有一个程序站在它和你的电脑之间：模型说“我想读 `pager.py`”，这个程序去读，把内容交还给模型；模型说“我想运行 `pytest`”，这个程序去运行，把输出交还给模型。如此反复，直到任务完成。这个中间程序就叫 **Agent 运行时**（也叫 harness）。Keelson 就是这样一个运行时。

打个比方：模型是一位很聪明、但被关在玻璃房里的顾问，只能递纸条。Keelson 是站在房间外面的助理——接过纸条，判断这件事能不能做，能做就去做，然后把结果写在纸条上递回去。

既然每张纸条都经过它，运行时就有机会做几件模型自己做不了的事：

| 模型自己做不到的事 | Keelson 怎么做 | 对应的概念 |
|---|---|---|
| 判断一个操作是否危险 | 每个请求执行前先检查；删文件、推代码这类操作停下来问你 | **权限门** |
| 发现自己在原地打转 | 同一个工具反复调用且结果不再变化时叫停 | **循环保护** |
| 在很长的任务里不“失忆” | 对话太长时，把旧内容压缩成结构化摘要 | **上下文折叠** |
| 记住你上次说过的偏好 | 把你的长期反馈沉淀成可复用的规则，并检查新规则不比旧的差 | **技能与自进化** |
| 事后说清楚自己做了什么 | 每一步都作为事件记录下来，可以原样回放 | **轨迹与回放** |

这五件事就是这个项目的全部重点。下面的步骤会让你逐个亲眼看到。

## 第一步：把它跑起来（不需要 API Key）

需要：Python 3.11 或更新版本，以及 git。

```bash
git clone https://github.com/ALTERLK/keelson.git
cd keelson
```

然后运行启动脚本。它会创建虚拟环境、安装依赖、启动控制台并打开浏览器：

```bash
start.bat        # Windows：也可以直接双击
./start.sh       # macOS / Linux
```

浏览器会打开 `http://localhost:8765`。此时还没有配置模型，所以控制台处于**回放模式**：你可以观看录制好的真实运行，但不能发起新任务。这正好——先看懂，再动手。

> 不想装任何东西？在线演示页 <https://alterlk.github.io/keelson/> 就是同一个控制台的回放模式。

## 第二步：看一次带讲解的回放

打开后是“概览”页。点击 **“看一次带讲解的回放”**。

你会看到一次真实录制的运行：用户说“`test_pager.py` 里有测试失败了，请修复”，然后 Agent 开始工作。讲解模式会在关键步骤停下来解释，点“继续”往下走。请留意这几处：

1. **每个工具调用都是一张卡片。** `read_file`、`edit_file`、`run_shell` 各有各的样子：读文件显示源码，改文件显示 diff，跑命令显示终端输出。
2. **每张卡片右上角都有“权限门：放行”。** 没有任何操作是绕过检查直接执行的。读文件是安全操作，所以直接放行。
3. **右侧检查器在实时计数。** 轮次、工具调用次数、Token 用量、权限门放行/询问/拒绝各多少次。
4. **检查器的“耗时”标签页**把这一轮的时间画成瀑布图。你会发现绝大部分时间花在等模型上，运行时自己的检查几乎不占时间。

看完第一条，去左侧“运行轨迹”再看第二条：**“权限门拦下危险命令”**。这次用户让它删文件，你会看到运行时停下来弹出确认框，用户点了拒绝，模型收到“被拒绝”的结果后**没有换个方法硬删**，而是如实告诉用户文件还在。这就是权限门的意义。

## 第三步：接上一个模型

Keelson 自己不带模型，需要你提供一个模型服务的 API Key。任何 OpenAI 兼容或 Anthropic 兼容的服务商都可以（DeepSeek、各类中转网关、OpenAI、Anthropic 等）。

先停掉刚才的服务（在终端里按 `Ctrl+C`），然后：

```bash
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # macOS / Linux

keelson init
```

`keelson init` 会一步步问你：选哪类服务商、接口地址、模型名、API Key（输入时不显示），然后写出 `.env` 文件并自动检查能否连通。

任何时候觉得“好像哪里不对”，运行：

```bash
keelson doctor
```

它会逐项检查并告诉你怎么修：

```text
✓  Python            3.12.13
✓  API key           configured (51 characters)
✓  Endpoint          https://…/v1 · OpenAI-compatible · model …
✓  Model answers     … answered (ok)
✓  git               found on PATH
!  rg                not found — ripgrep makes grep_search much faster; a Python fallback is used without it
✓  Web console       fastapi and uvicorn are installed
✓  State directory   ~/.keelson
```

✗ 是必须修的，! 只是建议。`.env` 已经在 `.gitignore` 里，不会被提交。

## 第四步：给它第一个任务

**重要：Keelson 在“当前目录”里工作。** 你在哪个目录启动它，它就读写哪个目录的文件。第一次请找一个不怕弄乱的目录：

```bash
mkdir playground
cd playground
keelson web
```

浏览器打开后，左下角状态会从“回放”变成“实时 · 模型名”。进入“控制台”页，在输入框里先试一个只读任务：

> 这个目录里有什么？

然后试一个要动手的：

> 写一个 fizzbuzz.py，再写一个测试文件，然后运行测试。

写新文件时它会停下来问你（创建新文件需要确认），点“允许一次”。运行测试时，你会看到命令的输出**一行行实时出现**在终端卡片里。如果命令跑太久，点“停止”，它会真的被终止。

喜欢终端？不加 `web` 就是命令行版本，功能相同：

```bash
keelson                          # 进入交互界面
keelson "解释一下这个项目"        # 只跑一个任务就退出
```

## 第五步：体会权限门

输入框下方有“权限模式”，决定 Agent 可以不问你就做多少事：

| 模式 | 读文件 | 改已有文件 | 新建文件 | 危险命令（删除、推送等） | 适合 |
|---|---|---|---|---|---|
| `default` 默认 | 直接做 | 直接做 | 问你 | 问你 | 日常使用 |
| `acceptEdits` 接受修改 | 直接做 | 直接做 | 直接做 | 问你 | 你信任它改代码时 |
| `dontAsk` 不询问 | 直接做 | 直接做 | 拒绝 | 拒绝 | 无人值守、CI |
| `plan` 计划（仅命令行） | 直接做 | 拒绝 | 拒绝 | 拒绝 | 先看方案再动手 |
| `bypassPermissions`（仅命令行 `--yolo`） | 直接做 | 直接做 | 直接做 | 直接做 | 一次性的沙箱环境 |

网页上故意选不了最后一种：关掉权限门只能在命令行上决定。

做个实验。在 `default` 模式下输入：

> 用 shell 命令把 fizzbuzz.py 删掉。

确认框弹出来时点**拒绝**，观察模型的反应：它会收到“这个操作被用户拒绝了”，然后停下来告诉你，而不是换一条命令再试。

## 第六步：让它记住你的偏好

先让它解释一段代码，然后说一句**长期有效**的要求：

> 以后解释代码时，一律用要点列表，每条不超过一行。

再让它解释另一段代码。这一次它会自动按要点列表来写——因为你那句话被提取成了一条**技能**，保存在 `.keelson/skills/` 下，之后遇到同类任务会被自动取出来套用。

技能不是想改就改的。如果你后来又给了一条反馈，要更新这条技能，新版本必须通过“非劣门禁”：拿这条技能自己的历史用例，把新旧两个版本都跑一遍，新版本的表现不能比旧版本差，否则会被隔离、不会生效。“技能进化”页面展示了一次被采纳和一次被拦下的真实记录。

## 常见问题

**打开页面显示“回放”，输入框不能用。**
没有配置模型，或者服务是用 `--replay` 启动的。运行 `keelson doctor` 看看是哪一种；概览页的“当前安装状态”卡片也会直接告诉你。

**`keelson` 命令找不到。**
没有激活虚拟环境。先运行 `.venv\Scripts\activate`（Windows）或 `source .venv/bin/activate`。

**`keelson doctor` 的 “Model answers” 是 ✗。**
Key 配置了但连不通。看那一行给出的错误：`401` 是 Key 不对；`404` 通常是模型名或接口地址不对。注意一个规则：接口地址的路径里带 `/anthropic` 时走 Anthropic 协议，否则走 OpenAI 协议。

**它会不会乱改我的文件？**
它只在你启动它的那个目录里工作；默认模式下，新建文件和危险命令都要你点头。想更保守，用 `keelson --plan`：只读、只出方案、不做任何改动。

**用起来贵不贵？**
费用完全取决于你选的模型。检查器里实时显示 Token 用量和估算成本；`--max-cost 0.5` 可以设一个上限，超过就停。

**回答是一下子全出来的，不是逐字出现。**
你的 `.env` 里设置了 `KEELSON_OPENAI_STREAM=0`（某些网关的流式接口不稳定时用它）。去掉这一行即可恢复逐字输出。
