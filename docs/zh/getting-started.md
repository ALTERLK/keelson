## 先弄明白它是什么

**大模型本身只会输出文字。** 你问它“帮我修一下这个 bug”，它能写出一段修复方案，但它碰不到你的文件，也跑不了测试。

要让它真的动手，得有一个程序站在它和你的电脑之间：模型说“我想读 `pager.py`”，这个程序去读，把内容交还给模型；模型说“我想运行 `pytest`”，这个程序去运行，把输出交还给模型。如此反复，直到任务完成。这个中间程序就叫 **Agent 运行时**（也叫 harness）。Keelson 就是这样一个运行时。

打个比方：模型是一位很聪明、但被关在玻璃房里的顾问，只能递纸条。Keelson 是站在房间外面的助理：接过纸条，判断这件事能不能做，能做就去做，然后把结果写在纸条上递回去。

既然每张纸条都经过它，运行时就能做几件模型自己做不了、或者做不可靠的事：

| | 模型自己做不好的事 | Keelson 怎么做 |
|---|---|---|
| **会自进化** | 记住你上次说过的偏好 | 把你的长期反馈沉淀成技能；新版本要先证明不比旧版本差才生效 |
| **不骗你** | 说“做完了、测试都过了”，其实没跑或没过 | 轮末自己去跑检查命令，按真实结果贴“已验证 / 未通过 / 未验证”徽章；没有证据的“通过”会被标出 |
| **不闯祸** | 判断一个操作是否危险 | 没有真删除，删除只进回收站；主目录、盘符根碰不得；撤不回的操作先问你并写明原因 |
| **不失忆** | 长任务里压缩上下文后，忘了你的要求 | 你的规则按原话记在任务账本里，压缩后原样放回 |
| **能撤销** | 改坏了退不回去 | 每轮开始前快照；`/undo` 连 shell 命令造成的改动一起还原 |

下面的步骤会让你逐个亲眼看到。

## 第一步：把它跑起来（不需要 API Key）

> **Windows 上不想装 Python？** 从 [Releases](https://github.com/ALTERLK/keelson/releases/latest) 下载压缩包，解压，双击 `Keelson.exe`，按[桌面版使用手册](desktop.md)走完三步就能用。压缩包里还有命令行版 `keelson-cli.exe`。下面的步骤可以直接跳到[第二步](#第二步看一次带讲解的回放)。
>
> 什么都不想装？在线演示 <https://alterlk.github.io/keelson/> 就是同一个控制台的回放模式。

从源码装需要 Python 3.11 或更新版本，以及 git。

```bash
git clone https://github.com/ALTERLK/keelson.git
cd keelson
```

然后运行启动脚本。它会创建虚拟环境、安装依赖、启动控制台并打开浏览器：

```bash
start.bat        # Windows：也可以直接双击
./start.sh       # macOS / Linux
```

浏览器会打开 `http://localhost:8765`。此时还没有配置模型，所以控制台处于**回放模式**：你可以观看录制好的真实运行，但不能发起新任务。这正好：先看懂，再动手。

## 第二步：看一次带讲解的回放

打开后是“概览”页。点击 **“看一次带讲解的回放”**。

你会看到一次真实录制的运行：用户说“`test_pager.py` 里有测试失败了，请修复”，然后 Agent 开始工作。讲解模式会在关键步骤停下来解释，点“继续”往下走。请留意这几处：

1. **每个工具调用都是一张卡片。** `read_file`、`edit_file`、`run_shell` 各有各的样子：读文件显示源码，改文件显示 diff，跑命令显示终端输出。
2. **每张卡片右边都有“权限门：放行”。** 没有任何操作能绕过检查直接执行。
3. **回答下面有一个“已验证”徽章。** 这不是模型说的：Keelson 核对过，最后一次改动之后测试真的跑过并且通过，才贴上它。
4. **右侧检查器在实时计数**：轮次、工具调用次数、Token 用量、权限门放行 / 询问 / 拒绝各多少次。“耗时”标签页把这一轮的时间画成瀑布图，你会发现绝大部分时间花在等模型上。

然后去左侧“运行轨迹”，再看另外几条：

- **“删除只进回收站”**：用户让它用 shell 删文件。shell 里的删除命令一律被拒绝，模型改用 `delete_files`，文件进了回收站。
- **“撤销连 shell 的改动一起撤”**：这一轮全用 shell 命令改文件、建文件。一次撤销，全部还原。
- **“撤销不了的才问”**：模型要装包，运行时停下来问，并写明“装包 /undo 撤不回来”；用户拒绝后，模型换了不需要装包的做法。

## 第三步：接上一个模型

Keelson 自己不带模型，需要你提供一个模型服务的 API Key。任何 OpenAI 兼容或 Anthropic 兼容的服务商都可以（DeepSeek、OpenAI、Anthropic、各类中转网关等），DeepSeek 有现成的预设。

先停掉刚才的服务（在终端里按 `Ctrl+C`），然后：

```bash
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # macOS / Linux

keelson init
```

`keelson init` 会一步步问你：选哪类服务商、接口地址、模型名、API Key（输入时不显示），然后写进 `~/.keelson/config.env` 并自动检查能否连通。这个文件在你的用户目录下，不在任何项目里，所以不会被提交；所有项目共用它。想给某个项目单独配，写在项目的 `.keelson/config.env` 里。

常在几个模型之间切换？`keelson init --profile 名字` 存成一个配置档，`keelson use 名字` 切换。

任何时候觉得“好像哪里不对”，运行：

```bash
keelson doctor
```

它会逐项检查并告诉你怎么修：

```text
✓  Python            3.12.13
✓  API key           configured (51 characters)
✓  Endpoint          https://…/v1 · OpenAI-compatible · model …
✓  Model answers     … answered (ok)
✓  git               found on PATH
!  rg                not found — ripgrep makes grep_search much faster; a Python fallback is used without it
✓  Web console       fastapi and uvicorn are installed
✓  State directory   ~/.keelson
```

✗ 是必须修的，! 只是建议。Key 的值不会被打印出来，只显示长度。

## 第四步：给它第一个任务

**重要：Keelson 在“当前目录”里工作。** 你在哪个目录启动它，它就读写哪个目录的文件。第一次请找一个不怕弄乱的目录：

```bash
mkdir playground
cd playground
git init
keelson web
```

`git init` 不是必须的，但有了 git，撤销能覆盖 shell 命令造成的改动（Keelson 用自己的快照仓库，不会动你的 `.git`）。

浏览器打开后，左下角状态会从“回放”变成“实时 · 模型名”。进入“控制台”页，在输入框里先试一个只读任务：

> 这个目录里有什么？

然后试一个要动手的：

> 写一个 fizzbuzz.py，再写一个测试文件，然后运行测试。

这次它不会停下来问你：新建文件、改文件、跑测试都在项目里，都能撤销，所以直接做。运行测试时，你会看到命令的输出**一行行实时出现**在终端卡片里；命令跑太久，点“停止”会真的终止它。

做完后，回答下面会出现验证徽章。它找到了 pytest，就会核对模型改完后有没有真的跑过并通过，没跑过就自己跑：✓ 已验证、✗ 未通过（附真实输出），或者 ! 未验证（项目里没有检查命令）。检查命令会自动识别；想固定下来，在终端里运行 `/verify init`，它会把识别出的命令写进项目根目录 `KEELSON.md` 的 `## Verify` 一节，之后改这个文件即可。

喜欢终端？不加 `web` 就是命令行版本，功能相同：

```bash
keelson                          # 进入交互界面
keelson "解释一下这个项目"        # 只跑一个任务就退出
```

终端里输入 `/help` 看全部命令，Shift+Tab 切换权限模式，Ctrl+C 打断当前这一轮。

## 第五步：体会权限门

Keelson 按**这个操作能不能撤销**决定要不要问你：

| 操作 | 结论 |
|---|---|
| 项目内的修改、新建文件、普通命令 | 直接做（快照覆盖，能撤销） |
| 用 `delete_files` 删项目里的文件 | 直接做（进回收站） |
| 装包、联网、`git push`、改写历史、写项目外的文件、MCP 工具 | 先问你，并写明原因 |
| 强推、`sudo`、`curl … \| sh`、路径里有没设置的变量 | 先问你，只能“允许一次” |
| shell 里的删除（`rm`、`del`、`Remove-Item` 等） | 拒绝，让模型改用 `delete_files` |
| 动主目录、盘符根、项目本身或它的上级；写系统目录 | 任何模式都拒绝 |

输入框下方的“权限模式”还能再调：

| 模式 | 做什么 | 适合 |
|---|---|---|
| 默认 | 按上表 | 日常使用 |
| 计划（只读） | 只读文件、写方案，不改任何东西 | 先看方案再动手 |
| 不询问 | 需要问的一律拒绝 | 无人值守、CI |
| `bypassPermissions`（仅命令行 `--yolo`） | 什么都不问，但上表最后一行照样拒绝 | 一次性的沙箱环境 |

网页和桌面版故意选不了最后一种：关掉询问只能在命令行上决定。

做两个实验。先输入：

> 用 shell 命令把 fizzbuzz.py 删掉。

shell 删除会被拒绝，模型会改用 `delete_files`，文件进回收站。去回收站能找回来，下一步的撤销也能把它放回去。

再输入：

> 装一下 requests 包。

这次会弹出确认框，写着装包 `/undo` 撤不回来。可以选“允许一次 / 本会话内都允许 / 在本项目中一直允许 / 拒绝”。点**拒绝**，还可以写个理由，模型会看到，然后停下来告诉你，或者换一种不用装包的做法。

细节和边界见[安全与撤销](safety.md)。

## 第六步：撤销

打开右侧检查器的 **审阅** 标签页：能看到每一轮改了哪些文件和 diff，每个文件可以单独**还原**，整轮可以**撤销这一轮**，撤错了点**反悔撤销**。

终端里是这几个命令：

| 命令 | 作用 |
|---|---|
| `/undo` | 还原上一轮改过的文件，包括 shell 改动、新建、删除的 |
| `/redo` | 反悔上一次 `/undo` |
| `/rewind N` | 撤销最近 N 轮 |
| `/revert 文件` | 只还原一个文件 |
| `/checkpoints` | 列出能撤销的轮次 |

试一下：让它“用 shell 命令新建一个 build 目录，在里面写个 report.txt，再往 fizzbuzz.py 末尾追加一行注释”，然后撤销这一轮。build 目录没了，fizzbuzz.py 也回到原样。

如果那一轮之后你自己又改过某个文件，撤销会停下来列出它，不会覆盖你的修改。撤不回的是装好的包、提交和推送、数据库、发到网络上的东西，这些正是第五步里要先问你的操作。

## 第七步：让它记住你的话

**这次任务里的规则。** 在对话里说一句：

> 不要改 test_ 开头的文件。

打开检查器的 **任务** 标签页，这句话按原话记在“你的规则”下面。对话很长、旧内容被压缩时，这些规则会原样放回，不会被总结丢。你也可以在那里直接加一条。

**长期的偏好。** 先让它解释一段代码，然后说一句**长期有效**的要求：

> 以后解释代码时，一律用要点列表，每条不超过一行。

再让它解释另一段代码。这一次它会自动按要点列表来写，因为你那句话被提取成了一条**技能**，保存在 `.keelson/skills/` 下，之后遇到同类任务会被自动取出来套用。

技能不是想改就改的。如果你后来又给了一条反馈，要更新这条技能，新版本必须通过“非劣门禁”：拿这条技能自己的历史用例，把新旧两个版本都跑一遍，新版本的表现不能比旧版本差，否则会被隔离、不会生效。“技能进化”页面展示了一次被采纳和一次被拦下的真实记录。

## 常见问题

**打开页面显示“回放”，输入框不能用。**
没有配置模型，或者服务是用 `--replay` 启动的。运行 `keelson doctor` 看看是哪一种；概览页的“当前安装状态”卡片也会直接告诉你。

**`keelson` 命令找不到。**
没有激活虚拟环境。先运行 `.venv\Scripts\activate`（Windows）或 `source .venv/bin/activate`。用的是发布包的话，命令是 `keelson-cli.exe`。

**`keelson doctor` 的 “Model answers” 是 ✗。**
Key 配置了但连不通。看那一行给出的错误：`401` 是 Key 不对；`404` 通常是模型名或接口地址不对。注意一个规则：接口地址的路径里带 `/anthropic` 时走 Anthropic 协议，否则走 OpenAI 协议。

**我以前的 `.env` 还能用吗？**
能。项目目录里的 `.env` 仍然会被读取，但优先级最低。建议用 `keelson init` 写到 `~/.keelson/config.env`，所有项目共用。

**验证徽章一直是“未验证”。**
Keelson 没找到检查命令。在项目根目录的 `KEELSON.md` 里加一节 `## Verify`，用列表写出命令（比如 `` `python -m pytest -q` ``）；终端里 `/verify` 可以看当前用的是哪些命令。

**它会不会乱改我的文件？**
它只在你启动它的那个目录里工作，改动都能撤销；撤不回的操作会先问你；删除只进回收站。动手前它会先声明要改哪些文件，改范围外的文件也会先问。想更保守，用 `keelson --plan`：只读、只出方案。

**用起来贵不贵？**
费用完全取决于你选的模型。检查器里实时显示 Token 用量、估算成本和缓存命中率；`/usage` 看汇总；`--max-cost 0.5` 可以设一个上限，超过就停。

**回答是一下子全出来的，不是逐字出现。**
你的配置里设置了 `KEELSON_OPENAI_STREAM=0`（某些网关的流式接口不稳定时用它）。去掉这一行即可恢复逐字输出。
