## 权限门与权限模式

**是什么。** 模型提出的每一个工具调用，在执行之前都要经过 `check_permission`，得到三种结论之一：放行、询问你、拒绝。Keelson 按**这个操作能不能撤销**来决定，而不是按它是哪个工具。

**解决什么问题。** 什么都问，人会养成不看就点“是”的习惯；什么都不问，一条坏命令就能删掉主目录。模型会犯错，也可能被文件里的恶意内容带偏。

**怎么判断。**

| 操作 | 结论 | 原因 |
|---|---|---|
| 项目内的修改、新建文件、普通命令 | 放行 | 检查点覆盖，`/undo` 能撤回 |
| 项目内的 `delete_files` | 放行 | 进回收站 |
| 装包、联网、`git push`、改写历史、写项目外的文件、MCP 和未知工具 | 询问，并写明原因 | `/undo` 撤不回 |
| 强推、`git clean -x`、发布、`sudo`、`curl … \| sh`、路径里有没设置的变量 | 询问，**只能允许一次** | 永远不能“一直允许” |
| 在 shell 里删除（`rm`、`del`、`Remove-Item`、`find -delete` 等） | 拒绝 | 改用 `delete_files` |
| 移动或删除主目录、盘符根、项目目录本身或它的上级；写系统目录 | 任何模式都拒绝 | 不该有任何操作这样做 |

判断路径之前，先展开 `~`、`$HOME`、`$env:USERPROFILE`、`%VAR%` 和 `$VAR`；复合命令（`a && b; c | d`）拆开逐段判断。细节和边界见[安全与撤销](safety.md)。

询问时你可以选：**允许一次 · 本会话内都允许 · 在本项目中一直允许**（写入 `.keelson/settings.local.json`）**· 拒绝**，或者拒绝并写上理由，模型会看到这个理由。“允许一次”不会被记住。

权限模式：

| 模式 | 区别 | 启动方式 |
|---|---|---|
| `default` | 按上表 | 默认 |
| `acceptEdits` | 与 default 相同（为兼容保留） | `--accept-edits` |
| `dontAsk` | 凡是要询问的一律拒绝（CI、子 Agent） | `--dont-ask` |
| `plan` | 不改文件、不跑命令，只写计划文件 | `--plan` 或 `/plan` |
| `bypassPermissions` | 什么都不问；“任何模式都拒绝”那一行照样拒绝 | `--yolo` |

想按工具单独放行或禁止，在 `~/.keelson/settings.json`（对所有项目生效）或 `.keelson/settings.json`（只对当前项目）里写规则，`deny` 优先于 `allow`：

```json
{
  "permissions": {
    "allow": ["run_shell(npm install*)", "run_shell(git push*)"],
    "deny": ["run_shell(git push*)", "edit_file(.env)"]
  }
}
```

括号里的模式匹配 shell 命令（复合命令的每一段都会单独匹配）或文件路径；以 `*` 结尾表示前缀匹配。

**工作区信任。** 克隆来的仓库可能在设置里带一条 `run_shell(*)`，或在 `.mcp.json` 里带一个 MCP 服务。所以项目的 *allow* 规则和 MCP 服务，要等你信任这个目录后才生效：终端会问一次，也可以运行 `keelson trust`（`--revoke` 撤销）。项目的 *deny* 规则立即生效。

**在哪里能看到。** 确认框里写着的原因；控制台每张工具卡片右上角的“权限门：放行 / 你已批准 / 拒绝”；检查器“权限门”一栏的计数。

**值得知道的细节。**

- 拒绝会作为工具结果返回给模型（你写了理由就带上理由），模型能换一种做法，而不是卡住。
- 子 Agent 的权限不会高于它的父 Agent。
- Web 控制台选不了 `bypassPermissions`。
- 这是护栏，不是沙箱：命令启动的测试或构建脚本，仍然能做你的账户能做的任何事。

## 撤销：检查点

**是什么。** 每一轮开始时，Keelson 给项目拍一个快照；`/undo` 把这一轮改过的文件全部还原——**包括 shell 命令改动、新建、删除的文件**。

**解决什么问题。** Claude Code 的检查点只跟踪它自己的改文件工具，官方文档写明不跟踪 bash 命令造成的改动。Agent 跑了格式化、代码生成或 `mv` 之后，就撤不回来了。

**怎么用。**

| 命令 | 作用 |
|---|---|
| `/undo` | 还原上一轮改过的文件 |
| `/undo --force` | 同上，连你在那一轮之后改过的文件也覆盖 |
| `/rewind N` | 撤销最近 N 轮 |
| `/redo` | 反悔上一次 `/undo` |
| `/revert 文件 [N]` | 只把一个文件还原到 N 轮之前 |
| `/checkpoints` | 列出可以撤销的轮次和涉及的文件 |

如果那一轮结束后你又改过某个文件，`/undo` 会列出它并停下，不会覆盖你的修改。撤销之后，模型会被告知哪些文件变了。

**原理。** 一个独立的 git 仓库，放在 `~/.keelson/projects/<哈希>/checkpoints/`，使用独立的索引；你项目自己的 `.git` 绝不会被碰。文件逐字节保存（不转换换行、不走过滤器、不跑钩子）。`node_modules`、`.venv` 等能重新生成的目录、`.gitignore` 忽略的文件、超过 50 MB 的新文件不进快照；被忽略的文件如果是 Keelson 自己的工具改的，会单独保存原样，所以 `/undo` 也能还原。

**覆盖不了的：** 装好的包、提交和推送、数据库、网络，以及 shell 命令改动的项目外文件。这些正是权限门会先问你的操作。没有 git 时，只有 Keelson 自己的文件工具能撤销，终端会明确提示，普通 shell 命令也会改为先询问再执行。

## 完工验证

**是什么。** 一轮改了代码，Keelson 会在这一轮结束前**自己**检查改动，并给这一轮打上徽章。徽章依据的是真正运行过的命令，不是模型写的话：

```
✓ Verified  pytest -q: 42 passed in 3.1s (run by Keelson at 14:02)
✗ Checks fail  pytest -q: 1 failed, 1 passed in 0.23s
! Not verified  no check command for this project: add a ## Verify section to KEELSON.md (/verify init)
```

**解决什么问题。** 编码 Agent 会在三种情况下说“做完了，测试都通过了”：根本没跑测试；跑了但没过；靠改测试让它通过。前两种是 Claude Code 用户在 issue 里反映的；第三种（“奖励投机”）有 EvilGenie 基准对 Claude Code 和 Codex 的测量。社区通常的补救是自己写 Stop 钩子。

**原理。**

- **跑哪些检查。** 优先用 `KEELSON.md` 里 `## Verify`（或 `## 验证`）一节：每个列表项是一条反引号包起来的命令，也可以写成代码块。没有这一节时，只自动识别测试：pytest（项目有 `.venv` 就用其中的 Python）、`npm`/`pnpm`/`yarn test`、`cargo test`、`go test ./...`。lint 和类型检查只有写进去才会跑。`/verify init` 把识别出的命令写进 `KEELSON.md`。
- **证据只看真正运行过的命令。** 本轮每次工具调用都按真实退出码记录。模型在最后一次改动之后已经跑过并通过的检查，不会重跑。同一条命令的不同写法也算同一条，例如 PowerShell 的 `& "...\python.exe"`。
- **改了代码的一轮结束时**，Keelson 补跑还没跑过的检查：
  - 和模型自己的命令走同一道权限门；需要你点头的检查会标为“未运行”，绝不背着你跑。补跑时带上 `CI=1`。
  - 失败时把真实输出交还模型，最多 `KEELSON_VERIFY_RETRIES` 次。要求它修好自己弄坏的地方，但**不要**为了修本来就失败的东西而扩大任务范围。
  - 如果模型的回答里已经说明哪些还没通过，就不再打回。
- **未经证实的说法。** 回答里出现“all tests pass”“测试全部通过”之类的话，却没有一次通过的运行记录可以对应，就列在徽章下面。
- **只改了文档的轮次**，以及没有检查命令的项目，结论为“未验证”，并写明原因。

**测试保护。** 任务不涉及测试时：

- **改动或删除已有的测试文件，要先问你。** `dontAsk` 模式下直接拒绝。
  - 新建测试文件、只加不删的修改，不会问。
  - 选“本会话”或“本项目”后不再问；`KEELSON_GUARD_TESTS=0` 关闭这项保护。
- **识别“削弱测试”的改动。** 方法是对比本轮开头的快照，能识别：
  - 删除测试、删除测试文件；
  - 加了 `skip`、`xfail`、`.only`；
  - 删除断言，或加了 `assert True`；
  - 改了期望值，例如 `assert f(2) == 4` 改成 `== 5`。

  识别到后先请模型还原一次，仍然存在的列在徽章下面。

**覆盖不了的。** Keelson 只能用你给的命令检查：测试没覆盖到的改动，照样会显示通过。计划模式和子 Agent 不做验证，子 Agent 的改动由父 Agent 那一轮一起验证。`KEELSON_VERIFY=0` 关闭完工验证。

## 任务账本：折叠后不失忆

**是什么。** 运行时在模型上下文之外维护的一份工作记录。每轮结束时保存；上下文被折叠时，**原样**放回：

- **目标**：开启这项工作的那条请求，按你的原话；
- **你的约束**：你说过的每一句像规则的话，例如“别动公开 API”“只改 parser.py”“always use pathlib”。加引号保存，绝不改写；
- **计划**：模型用 `update_task` 维护，每步带状态，终端里显示成待办清单；另有模型记下的**关键决定**；
- 到目前为止**改过的文件**，以及**最近一次验证结果**。

**解决什么问题。** 长任务压缩上下文之后，Agent 会忘掉约束和进度，接着干又把自己之前的成果弄坏。Claude Code 用户在 issue 里反映过这个问题。由模型自己写的总结，恰恰最容易丢掉这些细节。

**怎么用。** 全自动，另有几个命令：

- `/task` 查看账本；
- `/task add 规则` 和 `/task drop N` 增删约束，`/task goal 文字` 改目标，`/task clear` 清空；
- 折叠时会提示保留了什么，例如“kept word for word: the goal, 3 constraint(s) verbatim, the plan (2/5 done) …”；
- `--resume` 恢复会话时，账本一起恢复；
- 用 `exit` 退出时，你说过不止一次的规则会询问是否写进 `KEELSON.md`，你同意才写。

**局限。**

- 规则靠措辞识别，看的是中英文的标志词，例如“不要、必须、只、保持”和 *don't、never、always、must、only、keep*。没有这类词的规则识别不到，可以用 `/task add` 补上。
- 账本最多保留 40 条规则，满了以后先淘汰只说过一次的。

## 范围护栏：不乱改

**是什么。** 一个请求的改动只限于它涉及的文件。

- **范围是怎么来的。** 你用 `@` 提到的文件，加上模型用 `declare_scope` 声明的文件、目录或通配符（附理由）。范围会显示为 `◇ scope: …`。
- **越界要问。** 有范围时，改范围外的文件要先问你，并写明原因；`dontAsk` 模式下直接拒绝。你允许过的文件会并入范围。
- **轮末报告。** 列出范围外被改的文件。短请求产生大改动（不到 200 字的请求改了 8 个以上文件）时也会提醒。

**解决什么问题。** 让 Agent 修一个地方，它顺手“改进”了没人要求的代码，结果引入回归。Claude Code 用户在 issue 里请求过“严格范围模式”。

**局限，照实说。**

- 既没有声明范围、也没有 `@` 任何文件时，护栏不起作用。
- 模型可以再次 `declare_scope` 扩大自己的范围，不过每一次你都看得到。
- shell 命令不按范围检查，它们由 `/undo` 和权限门兜底。
- 每个新请求，范围重新计算。
- 选“本会话”或“本项目”后不再询问；`KEELSON_SCOPE_GUARD=0` 关闭护栏。

## 提示词缓存与成本

**是什么。** Keelson 让每次请求都只是在上一次的基础上往后追加。这样支持前缀缓存的服务商（DeepSeek、OpenAI、Anthropic）可以把对话的大部分按缓存命中价计费：

- 系统提示词里不放任何会在会话中变化的内容。git 分支和状态改为随你的消息发送，而且只在有变化时才发；
- “上下文快满了”的提示在越过阈值时只发一次，附在最新一条工具结果后面，不再改写系统提示词；
- 测试 `tests/test_ledger_scope.py` 检查：每次请求都以上一次请求的全部消息开头，逐字节一致。

用 DeepSeek 对同一个任务在改动前后各跑一次，按缓存命中计费的输入 token 占比从 43% 升到 82%。改动前，每次调用的缓存命中都停在约 3,000 个 token；改动后，命中量随对话一起增长。两边各只跑了一次，而且模型走的路线不同，所以只能当示例，不能当基准测试。

**用量。**

- 每轮结束的那一行会显示缓存命中率。
- 每轮往 `~/.keelson/usage.jsonl` 追加一条记录：项目、会话、模型、token、缓存命中、估算花费。
- `/usage` 按本会话、本项目今天、所有项目今天、最近 7 天和各模型分别汇总。
- 设置 `KEELSON_DAILY_BUDGET_USD` 后，当天估算花费达到上限就不再开始新的一轮。
- 花费是按标价估算的；缓存命中数是服务商报告的。

**DeepSeek 思考模式。** 之前的 `reasoning_content` 每次请求都会带回去：DeepSeek 文档要求，带工具的请求必须这样做。

## 项目说明文件：KEELSON.md、AGENTS.md、CLAUDE.md

Keelson 读取以下说明文件：

- 项目目录及其每一级上层目录中的 `KEELSON.md`、`AGENTS.md`（跨工具通用约定）和 `CLAUDE.md`；
- `~/.keelson/KEELSON.md`，放你在所有项目都适用的规则。

外层目录的文件排在前面，所以更深、更具体的文件优先。所有这些文件都支持 `@./路径` 引用其他文件；`.keelson/rules/*.md` 排在最后。

## 计划模式

**是什么。** 一种只读模式：Agent 可以读代码、搜索，但不能改文件、不能跑命令。它把方案写进一个计划文件，你批准之后才退出计划模式开始动手。

**解决什么问题。** 对于大改动，先看方案再让它动手，比事后回滚便宜得多。

**怎么用。** `keelson --plan "怎么重构这个模块？"`，或者在终端会话里输入 `/plan` 切换。计划模式的审批目前只在命令行里可用。

## 循环保护与预算上限

**是什么。** 两道保险：循环保护盯着最近 8 次工具调用，如果其中 6 次以上是同一个工具、**并且**结果已经不再变化，就跳过执行、让模型直接作答；预算上限则在轮次或成本超过设定值时停止。

几个细节，都是[实战案例](case-study.md)里暴露之后才改的：

- shell 命令按“程序 + 第一个参数”计数，而不是都算作 `run_shell`。所以连续 6 次 `python -c` 试探不会连带拦住之后的 `python -m pytest`。
- 折叠上下文不会清空这个窗口。以前会，而 `compact_context` 是模型自己能调用的工具——有一次运行里模型就靠它把保护重置了。
- 同一轮里触发 3 次之后，运行时不再只是提醒：它直接用一次不带工具的调用收尾。
- 模型返回空回复（没有文字、也没有工具调用）时会重试，最多 2 次，而不是当成“做完了”。

它**拦不住**的情况：每次试探的输出都略有不同。保护比较的是结果的哈希，输出只要有一点变化就不算重复（案例里 humanize #205 三轮都是这样失败的）。这种情况只能靠轮次上限兜底。

**解决什么问题。** 模型有时会陷入“换个参数再试一次”的循环。评测里就抓到过这种情况：180 次运行中有 15 次撞到轮次上限（见 [`bench/spiral-diagnosis.md`](../../bench/spiral-diagnosis.md)）。

**怎么用。** 循环保护默认开启（`KEELSON_LOOP_GUARD=0` 关闭）。预算用 `--max-turns 20`、`--max-cost 0.50` 设置。

**在哪里能看到。** 检查器“运行时保护”一栏的“循环保护”计数；命中时对话流里会出现一条提示。

**值得知道的细节。** 判断依据是工具名而不是完整参数，因为观察到的故障是“参数微调”而不是“完全重复”。连续读 6 个不同的文件不会触发：结果在变化。

## 上下文管理

**是什么。** 让长任务留在模型上下文窗口之内的三层手段，从便宜到贵：

1. **单条结果预算**——过大的工具结果写到磁盘，模型拿到预览和引用。
2. **修剪过期结果**——窗口占用到 60% 时，裁短旧的工具结果，保留最近的几条。
3. **折叠**——到 70% 时，由辅助模型把历史改写成三个结构化切片：情景记忆（发生了什么）、工作记忆（当前目标和下一步）、工具记忆（哪些做法有效、哪些失败）。

![上下文管理三层](../assets/diagrams/context.zh.svg)

**解决什么问题。** 任务一长，对话就会超出窗口。直接截断会让模型忘记任务目标；全量摘要又贵又丢细节。

**怎么用。** 自动进行。`/compact` 可以手动触发折叠。折叠后，任务账本会原样放回。

**在哪里能看到。** 检查器里的“上下文窗口”进度条和“上下文折叠”计数。

## 技能

**是什么。** 一条技能是一个带元数据的 `SKILL.md` 文件，描述“遇到某类任务时应该怎么做”。每轮开始时按任务内容检索（BM25），匹配的技能会被注入提示词，或者在一个独立的子 Agent 里执行。

**解决什么问题。** 让“这类事情我们一向这么做”不必每次都重新说一遍。

**怎么用。** 把文件放到 `.keelson/skills/<名称>/SKILL.md`（项目级）或 `~/.keelson/skills/`（用户级）。最小示例：

```markdown
---
name: commit-message
description: Write a conventional commit message for the staged changes
when_to_use: The user asks to commit, or asks for a commit message
---

1. Run `git diff --staged` to see what changed.
2. Write one summary line under 72 characters, in the imperative.
3. Add a body only when the reason is not obvious from the diff.
```

`/skills` 列出全部技能；`/<技能名> 参数` 直接调用某一条。

**在哪里能看到。** “技能进化”页面底部的“当前工作区的技能”。

## 技能自进化

**是什么。** 你在对话里给出的长期反馈（“以后都……”）会被自动提取成技能；对已有技能的更新必须通过**非劣门禁**。

**解决什么问题。** 手写规则没人愿意维护；而让模型自己随便改规则又很危险——一条从单次对话里提炼的新规则，可能悄悄破坏旧版本原本做对的事。

**流程。**

![技能是怎么演化的](../assets/diagrams/evolution.zh.svg)

1. **预筛**：这句话像不像长期有效的反馈？（纯规则判断，不调用模型，过滤掉大多数普通消息。）
2. **提取器**：从**用户的原话**里提取一条候选规则。证据只来自用户，不来自模型对自己的评价。
3. **维护者**：对照已有技能，决定新增、合并还是丢弃。
4. **非劣门禁**（仅合并时）：用这条技能自己的历史用例重放新旧两个版本。硬失败不能变多，通过率不能下降。
5. 通过 → 写入新版本、给旧版本留快照、生成一张“进化卡片”；未通过 → 候选被隔离，线上文件恢复原样，卡片照样生成。

**怎么用。** 正常对话即可。相关命令：`/skill-history <名称>` 看版本，`/skill-diff <名称>` 看差异，`/skill-rollback <名称>` 回滚，`/extract_now` 立即对当前对话做一次提取。`KEELSON_AUTO_SKILL_EVOLUTION=0` 关闭自动提取。

**在哪里能看到。** “技能进化”页面：一次被采纳和一次被隔离的真实记录，包含证据、候选规则、门禁的对比数字和文件 diff。详细说明见 [技能自进化](skill-evolution.md)。

## 长期记忆

**是什么。** 关于你和项目的事实（“这个项目用 pnpm”“用户偏好中文回复”），按项目保存成一个个小文件，跨会话有效。

**与技能的区别。** 记忆是**事实**，技能是**做法**。“测试命令是 `make test`”是记忆；“改完代码后要跑测试并贴出结果”是技能。

**怎么用。** 由 Agent 在对话中自己判断并写入（写新文件会经过权限门）。`/memory` 查看它记了什么。文件在 `~/.keelson/memory/` 下，可以直接编辑或删除。

## 终端界面

**是什么。** 交互式的 `keelson`：带历史和补全的输入行、底部状态栏、边流式输出边按 Markdown 排版的回答，以及查看和调整各项状态的命令。

**怎么用。**

- **Enter** 发送；**Alt+Enter**（或 Ctrl+J）换行；粘贴的一整段算一条消息。**↑/↓** 翻历史，历史保存在 `~/.keelson/history.txt`。
- **Tab** 补全 `/命令`（附说明）、消息里任意位置的 `@文件`，以及 `/add`、`/drop`、`/revert` 后面的文件名。只写文件名也行，比如 `@calc` 能找到 `src/util/calc.py`。
- **Shift+Tab** 切换模式：默认 → 自动接受改动 → 计划 → 默认。
- **Ctrl+C** 打断本轮，并结束它启动的命令；在输入行连按两次退出。**Ctrl+D**（Windows 上 Ctrl+Z 再回车）也能退出。
- 底部状态栏：模型 │ 模式 │ 上下文占用 │ 花费 │ 缓存命中率 │ 用 `/add` 加入的文件。
- `/add 文件...` 把文件加入对话：内容只发给模型一次，文件算在范围护栏的范围内，之后的轮次只提文件名。`/drop` 移出。
- `/diff [N]` 查看最近 N 轮的改动，包括 shell 造成的；`/review` 回顾上一轮的验证徽章、警示和改动的文件。
- `/status` 显示模型、模式、工作区、会话、上下文、花费、验证命令和 `/undo` 能撤销到哪；`/resume` 列出最近的会话，`/resume N` 重新打开；`/init` 生成一份初始的 `KEELSON.md`。
- 系统语言是中文时界面用中文，否则用英文；`KEELSON_LANG=zh|en` 可以指定。命令名保持英文。

**值得知道的细节。** 没有真正的终端时（管道、CI），或设置了 `KEELSON_SIMPLE_INPUT=1`，输入退回到普通的整行读取，回答按原文输出。`KEELSON_MARKDOWN=0` 关闭 Markdown 排版。

## 一次性与脚本调用：`keelson -p`

**是什么。** 执行一个请求，不问任何问题，stdout 上只输出回答——给脚本、git 钩子和编辑器用。

**怎么用。**

```bash
keelson -p "解释一下 src/app.ts"
git diff | keelson -p "审一下这个改动"
keelson -p --output-format json "修好失败的测试" > result.json
```

提示可以来自参数、stdin，或两者都有（stdin 内容接在后面）。需要确认的操作一律拒绝，并告诉模型原因，所以要事先选好模式（`--accept-edits`、`--yolo`）。进度和警告写到 stderr。`--output-format json` 输出一个对象：`result`、`verify`（轮末验证徽章）、`usage`（token、缓存命中、花费）、`model`、`session_id`、`error`。退出码：0 完成，1 轮末验证未通过，2 出错。

## 会话

**是什么。** 一场对话及其历史。终端里一次只有一个；Web 控制台可以同时开多个，各有各的历史、事件流和权限模式。

**怎么用。**

- 终端：`keelson --resume` 恢复上一次会话，`/resume` 列出最近的会话，`/resume N` 打开其中一个——消息、任务账本和折叠记忆一起恢复。`/clear` 清空当前对话。
- 控制台：左侧“会话”列表，`+` 新建，点击切换。下方“历史”里是已结束的会话，点开是只读回放，“继续这个会话”可以接着聊——服务重启之后也可以。

**值得知道的细节。** 多个会话**共用同一个工作目录**：隔离的是对话，不是文件。同时最多 8 个活跃会话，超出时最久没用的空闲会话会被收进历史。

## 轨迹与回放

**是什么。** 运行时把每一步都发布成一个事件；录制器把它们按行写成 JSON，这就是一条轨迹。回放就是把同一批事件重新喂给界面。

**解决什么问题。** “它刚才到底做了什么？”不必靠猜，也不必重新跑一遍。演示时也不依赖网络和 API Key。

**怎么用。**

- Web 控制台的每个会话都会自动录到 `.keelson/traces/`（`--no-record` 关闭）。
- “运行轨迹”页面列出录像；“讲解”会在关键步骤停下来解释，“回放”则连续播放。
- `keelson web --replay`：只回放，完全不需要模型。
- 回放条上可以调速度、拖动进度、跳到结尾。

**在哪里能看到。** “运行轨迹”页面，以及检查器的“时间线”标签页（原始事件列表）。

## 耗时与成本

**是什么。** 循环的每一步（模型调用、权限检查、工具执行、技能检索、上下文折叠、等待用户确认）都带计时。

**怎么用。**

- 控制台检查器的“耗时”标签页：当前这一轮的瀑布图，一眼看出时间花在模型上还是工具上。
- “评测结果”页面底部：所有录像的 P50 / P95 汇总。
- `python scripts/perf_report.py [目录]`：在终端里出同一张表。
- `/cost`（终端）或检查器“本次会话”一栏：Token 用量和估算成本。

## MCP 工具

**是什么。** [Model Context Protocol](https://modelcontextprotocol.io) 是一种让外部程序向 Agent 提供工具的标准。Keelson 可以连接 MCP 服务，把它们的工具交给模型使用。

**怎么用。** 把 `.mcp.example.json` 复制为 `.mcp.json` 并按需修改：

```json
{
  "mcpServers": {
    "context7": { "command": "npx", "args": ["-y", "@upstash/context7-mcp"] }
  }
}
```

第一次需要时才连接。MCP 工具默认不受信任：每次调用都要确认，除非你在 `settings.json` 里显式放行。项目 `.mcp.json` 或 `.keelson/settings.json` 里的服务，要等你信任该目录后才会启动（见上文“工作区信任”）。

## 子 Agent

**是什么。** 主 Agent 可以把一块相对独立的工作（比如“在整个仓库里找出所有用到这个函数的地方”）交给一个子 Agent。子 Agent 有自己独立的上下文，做完只把结论交回来。

**解决什么问题。** 大量的搜索和阅读会迅速占满主对话的上下文。交给子 Agent，主对话里只留下结论。

**怎么用。** 由模型在需要时自行启动，不需要你操作。子 Agent 的权限不会超过主 Agent。

## doctor 与 init

**是什么。** 两个帮你把安装弄对的命令。

- `keelson init`：一步步生成 `.env`（选服务商、填接口地址、模型名、API Key），然后自动检查。
- `keelson doctor`：检查 Python 版本、是否配置了 Key、模型是否真的能回答、git 和 ripgrep 是否可用、Web 依赖是否装了、状态目录是否可写，每一项不通过都给出修复方法。`--offline` 跳过联网检查。

**在哪里能看到。** 控制台“概览”页的“当前安装状态”卡片显示的就是同一份检查结果。

## 环境变量

写在 `.env` 里，或直接设为环境变量。

| 变量 | 作用 | 默认 |
|---|---|---|
| `OPENAI_API_KEY` + `OPENAI_BASE_URL` | OpenAI 兼容服务 | — |
| `ANTHROPIC_API_KEY` + `ANTHROPIC_BASE_URL` | Anthropic 官方 | — |
| `APIKEY` + `API` | 通用写法；地址路径含 `/anthropic` 走 Anthropic 协议，否则走 OpenAI 协议 | — |
| `MODEL` | 模型名 | `deepseek-flash`（`deepseek-chat`、`deepseek-reasoner` 已于 2026-07-24 下线） |
| `KEELSON_PROFILE` | 使用哪个配置档（`~/.keelson/profiles/<名字>.env`）。`keelson use <名字>` 切换并记住，`keelson -P <名字>` 只用这一次，`keelson init --profile <名字>` 新建 | 无 |
| `KEELSON_SHELL` | Windows 上 run_shell 用哪个 shell：`pwsh`、`powershell`（5.1）、`cmd` | PowerShell（有 pwsh 7 用 7） |
| `KEELSON_CONTEXT_WINDOW`、`KEELSON_MAX_OUTPUT_TOKENS` | 覆盖模型登记表里的上下文规划窗口和每次请求的 `max_tokens` | 按模型 |
| `KEELSON_HOME` | 状态目录（会话、技能、记忆、检查点） | `~/.keelson` |
| `KEELSON_CHECKPOINTS` | 每轮给项目拍快照，`/undo` 才能用 | `1` |
| `KEELSON_CHECKPOINT_MAX_FILE_MB` | 超过这个大小的新文件不进快照 | `50` |
| `KEELSON_VERIFY` | 每轮结束时检查代码改动 | `1` |
| `KEELSON_VERIFY_RETRIES` | 检查失败时最多交还模型几次 | `2` |
| `KEELSON_VERIFY_TIMEOUT` | 每条检查命令最多运行多少秒 | `300` |
| `KEELSON_GUARD_TESTS` | 任务不涉及测试时，改已有测试要先问 | `1` |
| `KEELSON_SCOPE_GUARD` | 改本次请求范围外的文件要先问 | `1` |
| `KEELSON_DAILY_BUDGET_USD` | 当天估算花费（所有项目）达到此值后不再开始新的一轮 | 无 |
| `KEELSON_TRUST_ALL` | 把所有目录都当作已信任（只用于自己的机器和 CI） | `0` |
| `KEELSON_AUTO_SKILL_EVOLUTION` | 自动从反馈中提取技能 | `1` |
| `KEELSON_AUTO_SKILL_TARGET` | 新技能写到项目级还是用户级 | `project` |
| `KEELSON_JUDGE_MODEL` | 辅助判断用的模型（提取、门禁），可与主模型不同 | 同 `MODEL` |
| `KEELSON_LOOP_GUARD` | 循环保护 | `1` |
| `KEELSON_OPENAI_STREAM` | OpenAI 协议下是否流式；网关流式不稳定时设为 `0` | `1` |
| `KEELSON_TRACE` | 把计时写到本地日志文件 | `0` |
| `KEELSON_LANG` | 界面语言：`zh` 或 `en` | 跟随系统 |
| `KEELSON_MARKDOWN` | 在终端里把回答按 Markdown 排版 | `1` |
| `KEELSON_SIMPLE_INPUT` | 用普通整行输入代替带补全的输入行 | `0` |
